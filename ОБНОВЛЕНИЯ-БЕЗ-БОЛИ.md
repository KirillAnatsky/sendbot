# Автообновление (CI/CD) — настройка один раз

После этой настройки обновление выглядит так: **вносишь изменения → пушишь в
GitHub → через 2–3 минуты новая версия работает на сервере.** Никаких архивов
и копирования по SSH.

Заодно при каждом изменении автоматически прогоняются тесты, а если новая
версия не запустится — сервер сам вернётся на предыдущую.

---

## Шаг 1. Создать репозиторий (5 минут)

1. Зайди на **github.com**, зарегистрируйся (если нет аккаунта).
2. Справа вверху **+** → **New repository**.
3. Имя: `sendbot`, обязательно выбери **Private** (приватный!).
4. **Create repository**. Не закрывай страницу — оттуда понадобится адрес.

## Шаг 2. Залить код

На своём компьютере в Терминале (подставь свой адрес репозитория со страницы GitHub):

```bash
cd ~/Downloads
unzip -o sendbot-src.zip
cd "sendbot 9"

git init
git add .
git commit -m "Первая версия"
git branch -M main
git remote add origin https://github.com/ТВОЙ_ЛОГИН/sendbot.git
git push -u origin main
```

Файл `.env` с паролями в репозиторий **не попадёт** — он в списке исключений.

## Шаг 3. Дать GitHub доступ к серверу

**На сервере** (подключись `ssh root@IP-адрес`) выполни:

```bash
ssh-keygen -t ed25519 -f ~/.ssh/deploy_key -N ""
cat ~/.ssh/deploy_key.pub >> ~/.ssh/authorized_keys
echo "=== СКОПИРУЙ ВСЁ, ЧТО НИЖЕ, ЦЕЛИКОМ ==="
cat ~/.ssh/deploy_key
```

Скопируй вывод последней команды целиком — от строки `-----BEGIN…` до
`-----END…` включительно.

## Шаг 4. Прописать секреты в GitHub

В репозитории: **Settings** → слева **Secrets and variables** → **Actions** →
кнопка **New repository secret**. Добавь три штуки:

| Name | Secret (значение) |
|------|-------------------|
| `SERVER_HOST` | IP-адрес сервера, напр. `95.216.10.20` |
| `SERVER_USER` | `root` |
| `SSH_KEY` | тот длинный ключ из шага 3 (целиком) |

## Шаг 5. Переключить сервер на репозиторий

**На сервере**, один раз:

```bash
cd /opt/sendbot
git init
git remote add origin https://github.com/ТВОЙ_ЛОГИН/sendbot.git
git fetch origin
git reset --hard origin/main
chmod +x deploy.sh
```

Если репозиторий приватный, git попросит логин и пароль. Вместо пароля нужен
токен: GitHub → **Settings** (профиля) → **Developer settings** → **Personal
access tokens** → **Tokens (classic)** → **Generate new token**, галочка
**repo**, скопируй и вставь вместо пароля. Чтобы не вводить каждый раз:

```bash
git config --global credential.helper store
```

Готово. Проверить, что деплой работает:

```bash
cd /opt/sendbot && ./deploy.sh
```

## Как теперь обновлять

Правишь код у себя → в Терминале:

```bash
git add .
git commit -m "что изменил"
git push
```

Дальше GitHub сам: прогоняет тесты → если зелёные, заходит на сервер →
делает бэкап базы → обновляет → проверяет, что приложение живо. Если новая
версия не поднялась — автоматически возвращает предыдущую.

Смотреть, как идёт процесс: вкладка **Actions** в репозитории. Зелёная
галочка — обновление доехало, красный крест — не прошли тесты или деплой
(и на сервере осталась рабочая старая версия).

## Что делает деплой на сервере

1. Бэкап базы в `backups/predeploy-ГГГГММДД-ЧЧММСС.sql.gz`
2. Забирает новую версию кода
3. Пересобирает и перезапускает
4. 90 секунд проверяет, что приложение отвечает
5. Не ответило — откат на предыдущую версию

## Полезное

```bash
# запустить деплой вручную с сервера
cd /opt/sendbot && ./deploy.sh

# посмотреть, какая версия сейчас стоит
cd /opt/sendbot && git log -1 --pretty="%h %s (%cr)"

# откатиться на предыдущую версию руками
cd /opt/sendbot && git reset --hard HEAD~1 && ./deploy.sh
```

Кнопка «обновить вручную» есть и в GitHub: **Actions** → слева **Тесты и
деплой** → **Run workflow**.

## Тесты

Они гоняются автоматически, но можно и локально:

```bash
cd backend && pytest -q
```

Сейчас проверяется: сборка и валидация воронок, движок (сообщения, кнопки,
переходы, трекинг шагов), сегменты и фильтры, пароли и токены сессий,
изоляция подписчиков между ботами, deep-link метки, правила группировки
вложений, конвертация воронки для AI.
