# Что делать по шагам: база + тест

Порядок такой, потому что тестировать надо ту конструкцию, которая реально
поедет в бой. Сейчас в базе пусто — значит можно тестировать прямо на ней,
отдельный временный стенд не нужен.

```
1. Купить сервер под базу      → 15 минут, ~€4/мес
2. Перенести базу туда          → 10 минут
3. Залить 120к и померить       → 30 минут, с ноутбука
4. Стереть тестовые данные      → 1 команда
5. Запускать ботов
```

Шаги 1–2 расписаны в файле **БАЗА-НА-ОТДЕЛЬНОМ-СЕРВЕРЕ.md**. Сделайте их и
возвращайтесь сюда.

> Шаг 5 «перенести старые данные» из той инструкции можно пропустить —
> переносить нечего.

---

## Шаг 3. Тест

Нагрузку создаём **с ноутбука**, не с сервера. Иначе сервер одновременно и
держит нагрузку, и создаёт её — цифры получаются враньём.

### 3.1. Наливаем 120 тысяч подписчиков

На **сервере** (`ssh root@116.203.94.40`):

```bash
cd /opt/sendbot
docker compose -f docker-compose.prod.yml exec app python loadtest.py --subscribers 120000 --target 400000 --keep
```

Идёт минут 10–20. В конце выведет таблицу: сколько миллисекунд занимает
выборка сегмента, дашборд, аналитика — и прогноз на 400 тысяч.

`--keep` значит «не удалять данные сразу» — они нужны для следующего пункта.

### 3.2. Долбим админку с ноутбука

Пока 120 тысяч лежат в базе, открываем Терминал **на своём компьютере**:

```bash
pip3 install aiohttp
```

```bash
scp root@116.203.94.40:/opt/sendbot/backend/apitest.py ~/apitest.py
```

```bash
python3 ~/apitest.py --url https://funnels.win --login admin --password ВАШ_ПАРОЛЬ --users 30 --requests 100
```

Получите примерно такое:

```
  Успешных запросов: 3000 · ошибок: 0
  Пропускная способность: 180 запросов/с
  Время ответа:
    медиана (p50):       95 мс
    p95:                310 мс
  Вывод: отлично
```

Вот это и есть честная картина: 120 тысяч подписчиков в базе плюс 30 человек
одновременно в админке.

**Смотрим на p95** — это «почти самый медленный» ответ:

| p95 | что значит |
|---|---|
| до 500 мс | отлично, ничего не трогаем |
| 500–1500 мс | нормально, жить можно |
| больше 1500 мс | пора увеличивать сервер |

Хотите жёстче — поднимите `--users` до 50 и повторите.

## Шаг 4. Стереть тестовые данные

На сервере:

```bash
cd /opt/sendbot
docker compose -f docker-compose.prod.yml exec app python loadtest.py --cleanup-only
```

Скрипт удалит всё, что помечено `[LOADTEST]` — тестовых ботов, подписчиков,
теги и воронки. Ваши настоящие боты не тронет.

Проверьте глазами: зайдите в админку, раздел «Подписчики» — должно быть пусто
(или только ваши реальные).

## Куда смотреть, если медленно

| Что тормозит | Что делать |
|---|---|
| Дашборд и аналитика | увеличить сервер БД (CX22 → CX33) |
| Всё подряд, ошибки 502 | увеличить сервер приложения |
| Только рассылка | это не сервер, это лимит Telegram |

Увеличить сервер в Hetzner: карточка сервера → **Rescale** → выбрать тип →
сервер перезагрузится, минуты на две. Данные не теряются.

Рассылку сервер не ускорит вообще. Telegram даёт 30 сообщений в секунду на
бота: 400 тысяч на одном боте ≈ 3,7 часа, на пяти параллельно ≈ 45 минут.
Это потолок самого Telegram, а не наш.

## Если у вас УЖЕ есть живые подписчики

Тогда лить 120 тысяч фейков в боевую базу нельзя. Нужен одноразовый сервер:

Hetzner → Add Server → Ubuntu 24.04 → CX33 → name `sendbot-test`. На нём:

```bash
curl -fsSL https://get.docker.com | sh && apt install -y git
git clone ВАШ_РЕПОЗИТОРИЙ /opt/sendbot && cd /opt/sendbot
printf 'SECRET_KEY=test\nADMIN_LOGIN=admin\nADMIN_PASSWORD=test12345\nDB_PASSWORD=test12345\n' > .env
docker compose -f docker-compose.prod.yml --profile local-db up -d --build db app
```

Дальше шаги 3.1 и 3.2, только адрес `http://IP_ТЕСТОВОГО:8000`.
Потом Hetzner → `sendbot-test` → ⋮ → **Delete**, иначе капает счёт.
