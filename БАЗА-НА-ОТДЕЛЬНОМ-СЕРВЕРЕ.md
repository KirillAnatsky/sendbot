# База данных на отдельном сервере

Зачем: если основной сервер сломается, перезагрузится или его завалит нагрузочный
тест — данные останутся целы на другой машине. Плюс тест показывает честные цифры.

Делаем один раз, минут на 20. Копируйте команды по одной.

---

## Шаг 1. Создать второй сервер в Hetzner

1. Hetzner Cloud → ваш проект → **Add Server**
2. Location — **тот же, что у первого сервера** (Nuremberg / Falkenstein). Это важно.
3. Image — **Ubuntu 24.04**
4. Type — **CX22** (хватает; позже можно увеличить одной кнопкой)
5. Networking — раздел **Private networks** → **Create network**
   - Name: `sendbot`
   - IP range: оставьте по умолчанию `10.0.0.0/16`
6. SSH key / пароль — как в первый раз
7. Name: `sendbot-db` → **Create & Buy now**

## Шаг 2. Подключить первый сервер к той же приватной сети

1. Hetzner Cloud → сервер `sendbot` (первый, где приложение)
2. Вкладка **Networking** → **Attach to network** → выбрать `sendbot`

Теперь у каждого сервера есть внутренний адрес вида `10.0.0.2` и `10.0.0.3`.
Посмотреть его: карточка сервера → раздел Networks → колонка Private.

**Запишите:**
- внутренний адрес сервера с приложением: `10.0.0.__`
- внутренний адрес сервера с базой: `10.0.0.__`

## Шаг 3. Поставить Postgres на сервер с базой

Заходим на **новый** сервер (`ssh root@ВНЕШНИЙ_IP_БАЗЫ`) и вставляем блоками.

```bash
apt update && apt install -y postgresql
```

```bash
# создаём базу и пользователя (замените ПРИДУМАЙТЕ_ПАРОЛЬ на свой, без пробелов)
sudo -u postgres psql -c "CREATE USER sendbot WITH PASSWORD 'ПРИДУМАЙТЕ_ПАРОЛЬ';"
sudo -u postgres psql -c "CREATE DATABASE sendbot OWNER sendbot;"
```

```bash
# разрешаем слушать приватную сеть (подставьте свой 10.0.0.X — адрес ЭТОГО сервера)
echo "listen_addresses = 'localhost, 10.0.0.3'" >> /etc/postgresql/*/main/postgresql.conf
echo "host sendbot sendbot 10.0.0.0/16 scram-sha-256" >> /etc/postgresql/*/main/pg_hba.conf
systemctl restart postgresql
```

```bash
# закрываем всё, кроме SSH и постгреса из приватной сети
ufw allow OpenSSH
ufw allow from 10.0.0.0/16 to any port 5432
ufw --force enable
```

Проверка (должно вывести версию Postgres):
```bash
sudo -u postgres psql -c "select version();"
```

## Шаг 4. Переключить приложение на внешнюю базу

Заходим на **первый** сервер (`ssh root@116.203.94.40`):

```bash
cd /opt/sendbot
```

Дописываем в настройки адрес базы — подставьте свой пароль и адрес `10.0.0.X`:

```bash
printf 'DATABASE_URL=postgresql+asyncpg://sendbot:ПРИДУМАЙТЕ_ПАРОЛЬ@10.0.0.3:5432/sendbot\n' >> .env
printf 'DB_HOST=10.0.0.3\n' >> .env
printf 'DB_PASSWORD=ПРИДУМАЙТЕ_ПАРОЛЬ\n' >> .env
```

Перезапускаем:
```bash
docker compose -f docker-compose.prod.yml up -d --force-recreate app backup
```

Проверяем, что живо:
```bash
curl -s localhost:8000/api/health
```
Должно быть `"status":"ok"`.

> Локальный контейнер с базой теперь не запускается вообще — он спрятан за
> профилем `local-db`. Если когда-нибудь понадобится обратно:
> `docker compose -f docker-compose.prod.yml --profile local-db up -d db`

## Шаг 5. Перенести старые данные (если они были)

Только если на первом сервере уже накопились подписчики.

На **первом** сервере, ДО шага 4:
```bash
docker compose -f docker-compose.prod.yml --profile local-db up -d db
docker compose -f docker-compose.prod.yml exec -T db pg_dump -U sendbot sendbot > /root/dump.sql
```

Заливаем в новую базу:
```bash
apt install -y postgresql-client
PGPASSWORD='ПРИДУМАЙТЕ_ПАРОЛЬ' psql -h 10.0.0.3 -U sendbot sendbot < /root/dump.sql
```

Дальше делаем шаг 4.

## Бэкапы

Ничего не меняется: контейнер `backup` каждую ночь в 03:00 снимает дамп уже с
внешней базы и кладёт в `/opt/sendbot/backups`, хранит 14 последних копий.

Проверить, что бэкапы идут:
```bash
ls -lh /opt/sendbot/backups
```
