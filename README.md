# SendBot

Самописный аналог SendPulse под Telegram: бот на Python (aiogram 3) + веб-админка с визуальным конструктором воронок.

## Что умеет

- **Живой чат (как в SendPulse)** — клик по подписчику открывает переписку: вся история (входящие, ответы бота, сообщения оператора), поле для ручного ответа от оператора, панель с инфо (статус, дата, активность, язык, источник, бот), теги, ручной запуск воронки и пауза автоматизации (на время диалога воронки/автоответы не срабатывают).
- **Мультибот** — сколько угодно ботов, каждый со своим токеном и своей изолированной базой подписчиков. Одну воронку можно назначить на несколько ботов, или каждому боту дать свою. Раздел «🤖 Боты»: добавить, включить/выключить, поменять токен, статистика. Один процесс поднимает всех активных ботов.
- **Воронки** — drag-n-drop редактор: блоки «Сообщение» (текст + любое число вложений: фото, видео, аудио, голосовые, видео-кружки, файлы — несколько картинок/видео уходят альбомом; загрузка перетаскиванием, вставкой Ctrl/⌘+V или с диска), инлайн-кнопки, «Задержка» (мин/часы/дни), «Условие» (есть тег — да/нет), «Действие» (добавить/снять тег), «Заметка». Ветвление по кликам на кнопки. Мультивыделение (Shift+клик), копирование/вставка нод (Ctrl/⌘+C/V), в т.ч. **между воронками**, дублирование (Ctrl/⌘+D).
- **Триггеры** — /start, ключевое слово, добавление тега, **сообщение от юзера** (автоответ/fallback: срабатывает на любое сообщение, кроме /start и ключевых слов; можно ограничить «только если у юзера нет тега X»).
- **Сегментация (как в SendPulse)** — конструктор условий с объединением И/ИЛИ: тег (есть/нет), имя, @username, язык, статус (активен/заблокировал), источник (deep-link `/start <код>`), был в воронке, был в рассылке, дата подписки, последняя активность (за N дней / неактивен N дней), активен за 24 часа. Показывает число совпадений. Используется и в «Подписчиках» (фильтр), и в рассылках (точный выбор аудитории). Плюс авто-тегирование внутри воронки.
- **Рассылки** — по всей базе или по сегменту, с любыми вложениями (фото, видео, аудио, кружки, файлы, альбомы), rate-limit и прогрессом.
- **Кэш `file_id`** — каждый файл загружается в Telegram один раз на бота, дальше рассылается по идентификатору. На больших базах это экономит трафик в десятки раз и ускоряет рассылки (особенно с видео).
- **Автоочистка истории** — `HISTORY_RETENTION_DAYS` в `.env` (0 = хранить вечно): раз в сутки чистит переписку и получателей рассылок старше N дней, чтобы БД не разрасталась.
- **Подстановки** — `{first_name}`, `{last_name}`, `{username}` в текстах, HTML-разметка.
- **AI-сборка** — вставляешь текстовое ТЗ или загружаешь .docx (текст + картинки), Claude или OpenAI (свой API-ключ, раздел «🤖 AI-сборка») собирает черновик воронки; там же статистика по токенам. Тексты переносятся из ТЗ дословно. Сгенерированная воронка создаётся выключенной — проверь в редакторе и включи.
- **Блок «⚠️ Заметка»** — не отправляется подписчикам. AI ставит такие метки там, где по ТЗ чего-то не хватает (нет картинки/ссылки/лид-магнита, неясны сроки), чтобы ты это заметил и дозаполнил.
- **Картинки** — из .docx вытаскиваются автоматически в папку `media/` с маркером `[КАРТИНКА: media/файл.png]` на своём месте в тексте; бот отправляет их из `media/` или по http-ссылке.

## Запуск (Docker)

```bash
cp .env.example .env
# впиши ADMIN_PASSWORD (BOT_TOKEN больше не обязателен — ботов добавляют в админке)
docker compose up --build -d
```

Админка: http://localhost:8000 (пароль — из `.env`). Дальше: раздел «🤖 Боты» → добавь бота с токеном от @BotFather → включи → назначь ему воронку.

`BOT_TOKEN` в `.env` по-прежнему работает для обратной совместимости: если он задан и ботов ещё нет, при старте создаётся бот «Основной», и к нему привязываются существующие воронки/подписчики.

## Запуск без Docker (для разработки)

```bash
cd backend
pip install -r requirements.txt
BOT_TOKEN=... ADMIN_PASSWORD=admin uvicorn app.main:app --reload
```

Без `DATABASE_URL` использует SQLite (`sendbot.db`), без `BOT_TOKEN` поднимает только админку.

## Как собрать воронку

1. Теги → создай нужные теги (сегменты).
2. Воронки → «+ Новая воронка» → задай триггер сверху.
3. Добавь блоки из палитры, кликом по блоку открой настройки, «Применить».
4. Соедини блоки: тяни от выходной точки к входной. У «Сообщения» выход 1 — «далее», выходы 2+ — кнопки. У «Условия» выход 1 — «да», выход 2 — «нет».
5. «Сохранить», затем в списке воронок — «Включить».

## Как присылать ТЗ (чтобы AI собрал точнее)

Формат свободный, но чем понятнее структура — тем лучше результат. Рабочая схема:

- Разбивай на этапы/шаги. Заголовки этапов и таблицы .docx понимаются нормально.
- Тексты сообщений давай дословно (как они должны уйти подписчику) — их AI не переписывает. Служебные комментарии для маркетолога помечай, например, «(комментарий: …)», чтобы отделить от текста бота.
- Кнопки перечисляй прямо под сообщением: «Кнопки: Хочу бонус / Ищу стратегию / Просто интересно» — и указывай, куда ведёт каждая (в какой следующий шаг или на ссылку).
- Задержки пиши явно: «через 1 день», «на следующий день», «через 2 часа».
- Сегменты/теги называй словами: «повесить тег: лид», «если есть тег hot — …».
- Ссылки и картинки: вставляй картинки прямо в .docx (вытащатся сами) или пиши `[КАРТИНКА: media/имя.png]`; ссылки — обычным URL. Если чего-то ещё нет — так и напиши «ссылка будет позже», AI поставит блок «⚠️ Заметка».

## Демо-воронка

Готовый пример механики «сегментация кнопками → теги → лид-магнит по ветке → прогрев 5 дней с задержками → оффер (ссылка + кнопка интереса) → условие по тегу → дожим». Тексты — заглушки `[В СКОБКАХ]`, замени в редакторе на свои:

```bash
docker compose exec app python demo_funnel.py
```

## Структура

```
backend/app/
  main.py        # FastAPI + запуск бота и воркеров
  api.py         # REST API админки
  models.py      # схема БД (SQLAlchemy)
  graph.py       # компиляция графа Drawflow -> движок
  auth.py        # логин по паролю
  bot/
    runner.py    # aiogram: хендлеры, планировщик, рассыльщик
    engine.py    # исполнение воронок
    sender.py    # отправка с обработкой блокировок
  static/        # админка (SPA: app.js + editor.js на Drawflow)
```

## Ограничения MVP

- Один бот (токен в `.env`), один админ-пароль.
- Кнопки в воронке живут, пока существует запуск (клики по старым сообщениям после перезапуска воронки игнорируются).
- Нет alembic-миграций — схема создаётся автоматически; при изменении моделей проще пересоздать БД.
